# WarpGate 商用化对齐改造（参考 MailNest 形态）

## 目标
把现有接口整体升级为商用形态：**全接口 Bearer 鉴权 + {code,msg,data} 统一响应 + 业务状态码**；新增**固定 IP（专用实例绑定）**与粘性提取增强；新增 **API Key 管理页**和**内置 /docs 文档页**；最后部署到生产服务器。

## 一、server.js 改造

**1. 启用鉴权（替换 L211-213 空壳 `apiKeyAuth`）**
- 校验 `Authorization: Bearer <key>` 或 `x-api-key` 头，比对 `config.api_key`
- 覆盖**全部** `/api/*` 路由（含原先裸奔的 `/api/check`、`/api/containers`、`/api/stats`、`/api/job/:id`、`GET /api/config`）
- 失败返回 HTTP 401 `{code:"A0001"}`；静态页面（管理台/文档/key 页）不鉴权

**2. 响应格式对齐 MailNest**
- `success(res, data)` → HTTP 200 `{"code":"00000","msg":"","data":{...}}`
- `error()` → 业务错误 HTTP 200 + `{code:"Exxxx","msg":"...","data":null}`；鉴权 401 / 限流 429 / 内部错误 500 保留 HTTP 状态码
- 启用闲置的 `ERROR_CODES`（L171-180），改为字符串业务码：`00000` 成功、`A0001` Key 无效、`A0002` 限流、`P0001` 无可用代理、`S0001` 会话不存在、`I0001` 参数错误、`I0002` 实例不存在、`R0001` 实例操作失败、`99999` 系统异常

**3. 固定 IP（专用实例绑定）**
- pool 实例增加 `dedicated` 标记，**持久化到实例目录 meta.json**（服务重启恢复后仍是绑定状态）
- 新路由：
  - `POST /api/pool/dedicated/bind` `{name?}`——绑定指定或自动挑选一个可用健康实例，锁定其 IPv6，返回 `{name, proxy, ip}`
  - `POST /api/pool/dedicated/unbind` `{name}`——解除绑定归还普通池
  - `GET /api/pool/dedicated`——绑定列表
- **自动换 IP 全部豁免点**（绑定实例只记录告警日志、绝不自动重建/换 IP）：
  1. Round-Robin 与粘性新会话的候选过滤（L1613-1618）
  2. 健康巡检 4 个 rotate 触发点（L580/602-610/634-637/656-676）
  3. `probeCfOnAcquire` → `pending_rotate` → `rotatePendingIfAvailable`（L501-517）
  4. release/report 的 403 阈值直接 rotate（L1700-1708、L1770-1778）
  5. `/api/pool/rotate` 无参换全部 available（排除 dedicated）
  6. `adjustResidentCount` 缩容时**不删除**绑定实例
  7. `rotateInstanceIP` 入口加守卫（显式指定 name 的手动 rotate 除外——手动强制换 IP 但保持绑定）
- `/api/containers`、`/api/pool/status` 透出 `dedicated` 字段

**4. 粘性提取增强**：`acquire?session_id=x` 支持可选 `minutes` 参数（1~1440，默认仍取 `sticky_minutes`）

**5. API Key 管理**：新增 `GET /api/key`（返回完整 key）、`POST /api/key/reset`（重新生成 UUID 并落盘）

**6. 页面路由**：`/docs`、`/key` 显式路由 sendFile 到对应静态页

## 二、前端

**public/index.html（管理台）**
- `api()` 封装自动附带 `Authorization: Bearer <key>`（localStorage）；收到 401 弹出 Key 输入框（输错可重输），替代现在的无鉴权调用
- 所有响应解析从 `data.success` 改为 `data.code === "00000"`
- 顶栏加导航：管理台 / API Key / 文档
- 实例表格加「固定」徽章列 + 绑定/解绑按钮；统计卡增加「固定绑定」数
- API 使用面板的 curl 示例加上 `-H "Authorization: Bearer ..."`

**public/key.html（新，API Key 页）**
- 查看/隐藏/复制完整 Key（默认打码显示）、一键重置（确认弹窗，提示会使旧脚本失效）
- 展示带 Key 的 curl 快速示例

**public/docs.html（新，文档页，MailNest 式三栏）**
- 左侧分类导航：快速开始 / 基础说明（请求地址、鉴权方式、响应格式、状态码）/ 接口明细（acquire、release、report、rotate、status、dedicated bind/unbind/list、实例管理组）/ 错误码表 / 示例代码（curl + Python）
- 正文 + 右侧锚点目录；每个接口含：说明、方法路径、参数表、响应示例、可复制 curl
- 复用 index.html 的主题变量与组件样式，零依赖静态文件

## 三、测试与文档

2. 部署：执行 `deploy-v3.ps1`（SFTP 上传 + systemd 重启）到生产 192.6.121.16，部署后 curl 验证鉴权与提取
3. 不做 git 提交/推送（如需我再说）

## 兼容性影响（需要知晓）
- 现有业务脚本必须加 `Authorization: Bearer <key>` 头，一次迁移（Key 在 config.json / docker logs / key 页可查）
- 响应体从 `{success, data}` 变为 `{code, msg, data}`，旧脚本的判断字段要同步改
